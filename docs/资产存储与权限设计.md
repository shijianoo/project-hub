# 项目资产存储与权限设计

## 1. 设计目标

项目业务目录需要实时反映到服务器物理目录，但目录改名、移动和当前文件替换不能破坏历史版本。因此存储采用“工作区 + 不可变版本库”双层结构，数据库保存业务元数据和路径映射。

## 2. 物理目录结构

```text
AssetStorage.RootPath
├─ PH-001 - 示例项目 [12]                 可见项目工作区
│  ├─ STRUCTURE - 结构设计 [21]
│  │  └─ 正式图纸 [31]
│  │     └─ 总装结构图 [a1b2c3d4].dwg     仅当前版本
│  └─ SOFTWARE - 软件开发 [22]
├─ .versions                              隐藏不可变版本库
│  └─ 12/{storageKey}/v000001/content.dwg
├─ .staging                               上传暂存区
├─ .packages                              临时 ZIP
└─ .recovery                              孤立文件恢复区
```

物理名称包含项目、分类、目录业务名称和稳定 ID。资产工作文件包含 `StorageKey` 前八位，解决同名文件冲突并便于人工定位。

## 3. 一致性边界

- 数据库是业务结构、权限和当前版本关系的权威来源。
- `.versions` 是文件内容历史的权威来源。
- 可见项目工作区是可重建映射，不承担历史版本职责。
- 项目、分类和目录改名或移动时，物理目录先安全移动，再在数据库事务中批量更新 `WorkingRelativePath`。
- 资产标题、分类、目录或扩展名变化时，从当前不可变版本重新生成目标工作文件。
- 删除资产只移除工作映射并清空 `WorkingRelativePath`；恢复时重新发布。

## 4. 硬链接和复制回退

版本文件与工作文件位于同一资产根目录。系统优先创建硬链接：

- 不重复占用当前版本空间。
- 原子替换工作文件速度快。
- 工作文件删除或移动不会影响版本文件。

文件系统不支持硬链接时，自动退化为异步复制。激活使用目标目录内临时文件和原子覆盖，避免用户看到半写入文件。

## 5. 不可变版本

版本路径由 `ProjectId + StorageKey + VersionNumber` 唯一确定，同一路径存在时拒绝覆盖。数据库还记录：

- 原始文件名。
- MIME 类型和扩展名。
- 文件大小。
- SHA-256。
- 变更说明。
- 上传人和 UTC 上传时间。

同一资产上传新版本时使用 PostgreSQL advisory transaction lock 串行分配版本号。

## 6. 目录权限算法

权限优先级：

1. 系统管理员、项目负责人、项目管理员：完整权限。
2. 目录创建者且不是只读成员：编辑权限。
3. 目标目录显式 ACL。
4. 最近父目录显式 ACL。
5. 项目默认权限：成员只读，项目根目录对 Contributor 可编辑。

显式权限为 `None`、`Read`、`Edit`。Viewer 即使被错误提交 Edit，后端也会拒绝或降级。资产列表、详情、下载、ZIP 和通知接收人都会再次执行可见性过滤。

## 7. 存储健康检查

快速检查验证：

- 当前资产的预期工作路径。
- 工作文件是否存在、大小是否一致。
- 数据库 `WorkingRelativePath` 是否一致。
- 全部历史版本文件是否存在、大小是否一致。
- 工作区是否存在数据库之外的孤立文件。

深度检查额外计算工作文件和版本文件 SHA-256。

重建过程：

1. 确保项目、分类和全部逻辑目录存在。
2. 从当前不可变版本重新发布所有未删除资产。
3. 更新数据库工作路径。
4. 把非预期文件移动到 `.recovery/{projectId}/{timestamp}`。
5. 再次执行快速检查并返回结果。

重建不会覆盖或删除 `.versions` 中的任何历史版本。

## 8. 操作系统共享注意事项

ProjectHub 的目录权限属于应用层权限。如果把可见工作区直接作为 SMB/NFS 读写共享，员工可能绕过应用 ACL、审计、通知和版本历史。

推荐做法：

- 员工通过 ProjectHub 上传、预览、下载和打包。
- 物理工作区只授予应用服务账号写权限。
- 运维或备份账号可以只读访问资产根目录。
- 如未来必须提供企业文件共享，应对接 AD/LDAP 身份，并增加专门的操作系统 ACL 同步服务，不能简单复用当前应用角色名称。
