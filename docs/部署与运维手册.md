# ProjectHub 部署与运维手册

## 1. 推荐生产拓扑

- 一个 ProjectHub ASP.NET Core 实例，统一提供 API、Swagger 和 Vue 静态页面。
- PostgreSQL 独立服务。
- 一个持久化资产卷，必须与应用实例稳定绑定并定期备份。
- 可选 SMTP 服务。
- 外部使用 Nginx、Caddy、IIS 或企业网关终止 HTTPS。

## 2. Docker Compose 部署

复制环境变量模板：

```powershell
Copy-Item .env.example .env
```

至少修改：

- `POSTGRES_PASSWORD`
- `JWT_SECRET`，使用不少于 64 个随机字符。
- `INITIAL_ADMIN_PASSWORD`
- `PUBLIC_WEB_URL`

启动：

```powershell
docker compose up -d --build
docker compose ps
```

默认持久化卷：

- `projecthub-postgres-data`：PostgreSQL 数据。
- `projecthub-asset-data`：项目工作区、版本库、恢复区和临时打包目录。

不要只备份数据库而忽略资产卷；两者必须作为同一恢复点管理。

## 3. 非容器发布

```powershell
.\scripts\publish.ps1 -OutputPath artifacts\publish
```

将发布目录复制到服务器，配置以下环境变量或 `appsettings.Production.json`：

```text
ConnectionStrings__PostgreSql
Jwt__SecretKey
InitialAdmin__Password
AssetStorage__RootPath
Notifications__PublicWebUrl
```

运行账号必须对资产根目录拥有创建目录、读取、写入、移动和删除权限。建议资产根目录放在独立数据盘，不放在应用发布目录内。

前端生产构建会直接写入 API 的 `wwwroot`，并同步生成 `version.json`。ASP.NET Core 对 `index.html` 和 `version.json` 使用禁止缓存策略，对带内容哈希的 `/static` 资源使用一年不可变缓存，因此反向代理不应覆盖这些响应头。

## 4. SMTP

设置：

```text
Smtp__Enabled=true
Smtp__Host=smtp.example.com
Smtp__Port=587
Smtp__EnableSsl=true
Smtp__UserName=projecthub@example.com
Smtp__Password=应用专用密码
Smtp__FromAddress=projecthub@example.com
Smtp__FromName=ProjectHub
```

SMTP 失败不会影响站内通知。邮件发件箱会自动重试，超过最大次数后保留失败状态供运维检查。

## 5. HTTPS 与反向代理

生产环境必须使用 HTTPS。代理需要保留：

- `Host`
- `X-Forwarded-For`
- `X-Forwarded-Proto`
- HTTP Range 请求头，保证大文件和媒体断点访问。

上传限制同时受 Kestrel `MaxRequestBodySize` 和 `AssetStorage__MaximumFileSizeMb` 控制。代理层的上传限制应不小于应用配置。

## 6. 备份与恢复

数据库备份脚本：

```powershell
.\scripts\backup-postgres.ps1
```

完整备份建议步骤：

1. 暂停写入或进入维护窗口。
2. 执行 PostgreSQL 一致性备份。
3. 对整个资产根目录做快照或增量备份。
4. 记录数据库备份时间、资产卷快照时间和应用版本。

恢复时先恢复数据库和资产卷，再启动应用。启动后由项目管理角色执行“快速检查”，必要时执行“深度哈希检查”和“重建工作区”。

## 7. 资产目录运维规则

- `.versions`：不可变历史版本库，禁止人工编辑、覆盖和清理。
- `.staging`：上传暂存区，异常中断后可能存在临时文件，可在确认无上传任务时清理过期文件。
- `.packages`：临时 ZIP；下载响应关闭后会自动删除。
- `.recovery`：工作区重建时收纳孤立文件，确认无业务价值后再由管理员离线归档或清理。
- 其他项目目录：可见工作区，仅代表当前版本。

员工不应通过操作系统共享直接修改工作区，否则会绕过应用权限、审计和版本控制。若需要文件共享，应只通过 ProjectHub 页面和 API 使用；物理目录主要用于本地落盘、备份和服务器运维检查。

## 8. 健康检查与日志

- `/health`：进程健康状态。
- `/swagger`：API 文档和受控调试入口。
- `/version.json`：当前前端版本，供浏览器检测新版本；必须保持不缓存。
- 系统管理中的“操作日志”：记录用户、HTTP 方法、路径、耗时和状态码。
- 资产中心中的“物理存储健康检查”：检查缺失、内容不一致、版本损坏和孤立文件。

发生磁盘空间不足、权限错误或文件缺失时，应先停止继续上传，保留数据库和资产卷现场，再执行备份和定位。

## 9. 升级

升级前必须：

1. 备份数据库和资产卷。
2. 在测试环境运行 `dotnet test`、`pnpm typecheck` 和生产构建。
3. 检查配置项变化。
4. 在维护窗口替换应用。
5. 验证登录、工时查询、资产下载、Swagger 和健康检查。

当前开发阶段允许直接调整模型；进入生产运营后，应改用版本化数据库迁移，禁止直接删除字段或重建生产数据库。
