# ProjectHub 开发文档

## 1. 解决方案结构

```text
ProjectHub.slnx
├─ src/ProjectHub.Domain          领域枚举、实体和公共基类
├─ src/ProjectHub.Application     应用接口、契约 DTO、统一响应和业务异常
├─ src/ProjectHub.Infrastructure  SqlSugar、业务服务、认证、通知和物理存储
├─ src/ProjectHub.Api             ASP.NET Core 控制器、中间件、Swagger 和静态托管
├─ src/ProjectHub.Web             vue-pure-admin 前端项目
└─ tests/ProjectHub.Tests         xUnit 单元测试
```

依赖方向为：`Api → Infrastructure → Application → Domain`。Domain 不依赖上层项目，Application 只描述用例和契约，Infrastructure 实现业务和持久化。

## 2. 后端规范

- 使用文件范围命名空间、可空引用类型和隐式 using。
- 遵循微软 .NET 命名与格式规范；公开类型、接口和 API 使用中文 XML 注释。
- 数据库特性单独放在类或属性上方，不与声明写在同一行。
- 控制器仅负责 HTTP 输入输出转换，业务校验集中在应用服务。
- 少量简单参数可以直接写在一行；参数较多时使用 Request 类型。
- 只有上传、打包、哈希检查和工作区重建等确实需要取消的操作传递 `CancellationToken`。
- 业务错误使用 `BusinessException`，包含稳定错误码和 HTTP 状态码。
- 所有时间戳在数据库和接口内部统一使用 UTC，前端负责本地展示。

## 3. 数据库与 SqlSugar

`DatabaseInitializer` 在启动时执行：

1. 补齐项目成员最终版专业岗位字段，并由 SqlSugar CodeFirst 初始化或同步表结构。
2. 创建 PostgreSQL 唯一索引和查询索引。
3. 写入系统角色、工时规则、初始管理员和默认资产分类。
4. 确保项目、分类和逻辑目录存在对应物理工作目录。

开发阶段不保留旧字段兼容逻辑。模型发生不兼容变更时，可以重建开发数据库：

```sql
DROP DATABASE projecthub WITH (FORCE);
CREATE DATABASE projecthub;
```

该操作会删除开发数据，只能在确认目标数据库后手动执行，生产环境必须使用正式迁移和备份流程。

## 4. 认证和权限

- 登录返回访问令牌和刷新令牌。
- 访问令牌默认 30 分钟，用于 `Authorization: Bearer`。
- 刷新令牌默认 14 天，仅保存哈希，刷新后执行轮换并撤销旧令牌。
- 登录验证码一次性消费，错误答案同样会使挑战失效。
- 系统角色控制系统级能力，`ProjectRole` 控制单个项目内的操作权限。
- `ProjectJobRole` 是独立的专业岗位标志枚举；API 使用岗位数组，数据库使用 `JobRoleMask` 位掩码，并由 `ProjectJobRoleExtensions` 统一转换。
- `ProjectMember.CustomJobTitle` 保存“其他岗位”的自定义名称，`Responsibility` 保存成员在该项目内的工作边界和交付责任。
- `ProjectAccessService` 集中计算项目权限。
- `ProjectAssetAuthorizationService` 计算目录权限继承快照，所有资产查询、下载、通知和打包都复用该快照。

## 5. 资产模块

核心服务：

- `ProjectAssetService`：分类、资产、版本、回收站、ZIP、存储检查和重建。
- `ProjectAssetFolderService`：目录 CRUD、移动和成员 ACL。
- `ProjectAssetAuthorizationService`：项目角色、目录所有者、显式 ACL 和继承。
- `ProjectAssetStorage`：暂存、不可变版本提交、硬链接/复制、原子激活、目录同步和恢复区。

上传流程：

1. 把上传流写入 `.staging`，同时计算 SHA-256。
2. 在目标目录旁准备工作文件，优先使用硬链接，不支持时复制。
3. 把暂存文件原子移动到 `.versions/{projectId}/{storageKey}/vXXXXXX`。
4. 原子激活工作文件。
5. 在数据库事务中写入资产、版本和当前工作路径。
6. 数据库失败时补偿删除工作映射和新版本文件。

新版本使用 PostgreSQL advisory transaction lock 防止同一资产并发产生重复版本号。

## 6. 前端结构

业务 API 位于 `src/api/projecthub`，业务页面位于 `src/views/projecthub`。资产中心拆分为：

- `assets/index.vue`：工作区布局、目录树、筛选、列表和管理对话框。
- `AssetUploadDialog.vue`：拖拽批量队列、并发上传和重试。
- `AssetDetailDrawer.vue`：资产详情、版本历史、下载和新版本上传。
- `FolderPermissionDialog.vue`：项目成员目录 ACL。
- `AssetPreview.vue`：统一预览路由。
- `ModelPreview.vue`：Three.js 三维模型预览。
- `assets/utils.ts`：类型元数据、格式推断和显示工具。

项目团队页面通过 `src/utils/projectMember.ts` 统一维护项目权限、专业岗位分组和显示名称，项目中心与资产目录授权页面共享同一份元数据。

普通业务页面组件使用 `route.path` 作为渲染 key，查询参数仅表示筛选、目录和资产详情等页面状态，不得因查询参数变化销毁整个页面。`LayFrame` 仍按完整地址管理独立 iframe 实例。资产详情加载使用递增令牌丢弃过期异步结果，避免快速切换资产或版本时旧请求覆盖新状态。

前端通过 Axios 拦截器自动携带访问令牌。访问令牌过期时，只允许一个刷新请求，其余请求排队等待新令牌。

## 7. API 和 Swagger

Swagger 注册在 `Program.cs`。构建时生成 XML 文档，Swagger 合并：

- `ProjectHub.Api.xml`
- `ProjectHub.Application.xml`
- `ProjectHub.Domain.xml`

新增控制器接口时必须添加 `<summary>`；新增公开 DTO 属性时应补充必要注释。开发环境和生产环境均可按部署策略访问 `/swagger`。

## 8. 测试和质量检查

```powershell
dotnet test .\ProjectHub.slnx -c Debug --no-restore
Set-Location .\src\ProjectHub.Web
pnpm typecheck
pnpm lint:eslint
pnpm lint:stylelint
pnpm build
```

当前测试覆盖统一接口契约、密码、JWT、验证码、项目专业岗位位掩码和资产双层存储。新增权限算法、目录循环、文件补偿或版本并发逻辑时，应同步增加测试。
